# Classroom collaboration recovery

Collaboration sessions remain bound to an existing authorized document. A successful empty snapshot response starts an empty document; a missing document is terminal and is never recreated from old token claims. Reuse of a logical room validates its document UUID. A replacement can evict the old room only after the old target is confirmed absent, and state is not transferred between document identities.

Snapshots retain immutable serialized Yjs updates independently of idle-room lifetime. Acknowledgment removes only the version sent; edits received during the save remain pending. Fetches abort after five seconds, saves use at most four concurrent requests, transient failures retry with jitter up to a sixty-second delay, and automatic recovery stops after fifteen minutes. Terminal unsaved state remains in the bounded in-process queue. A fresh authorized rejoin is an explicit recovery action for that state. Confirmed missing documents instead invalidate the session. Pending state is not durable across process loss before acknowledgment; deployments require queue drain.

Each snapshot respects the API's one-million-byte limit. The pending payload budget is 64 MiB with at most 4096 entries; at most four in-flight older snapshots add bounded transient overhead. Capacity is validated against a candidate Yjs state before accepting an inbound document update. Capacity/terminal failures stop editable synchronization and show an unsaved-state message rather than silently discarding existing pending edits.

## Protocol compatibility

Yjs message type 4 is a recovery control envelope: a varuint message type followed by a JSON varstring. Frames are at most 256 bytes. Server `hello` has `{type:"hello",version:1,liveness:true}`. Only after this capability is advertised does a new client send `{type:"probe",version:1,nonce:"<16 lowercase hex characters>"}`. Server replies with the corresponding `ack`; nonmatching or retired-session acknowledgments do not certify liveness. One probe per five seconds per socket is accepted. Old clients ignore the unknown server message; new clients send no probes to old servers. Game/external-activity subprotocols retain their own command framing and existing recovery behavior.

`COLLABORATION_RECOVERY_PROBES_ENABLED` defaults to false. A enabled negotiated Yjs session checks responsiveness after online/foreground transitions, coalesces concurrent wake triggers, and replaces a nonresponsive socket while keeping its local Yjs runtime. The foreground probe deadline is five seconds. Fresh-token requests are bounded to five seconds and stale completions cannot attach to a different generation. A wake recovery reaches synchronization or an explicit error within thirty seconds under the accepted fault matrix. Hiding the tab cancels its probe deadline; it does not retroactively classify a sleeping browser as an active-session failure.

Close code 4404 means the document is unavailable and invokes current authorized document resolution. Close code 4409 means persistence cannot safely continue and stops automatic reconnect; the localized reconnect action explicitly retries without remounting the lesson. Policy denial also stops automatic retries. The existing heartbeat still closes abandoned sockets within sixty seconds after more than one missed pong. Media, lesson completion, attendance, routing, devices and material selection are not changed by collaboration recovery.

## Evidence and diagnostics

The 2026-10-05 review found heartbeat terminations at three times during the 09:30 lesson and eleven snapshot HTTP 404 responses for ten documents absent at later inspection. Synthetic-versus-user attribution and actual data loss are unconfirmed. Snapshot outcome logs contain only the closed enum `retry|document_invalid|unsaved`, fixed event `snapshot_outcome` and severity; document IDs, credentials, contents and raw exceptions are excluded. Existing snapshot metrics report saved/retry/terminal-invalid outcomes; retained unsaved work is not counted as discarded.

Acceptance uses two-browser Yjs convergence, persistence acknowledgment and restore into a new runtime, not merely fewer warnings. DEV and production delivery, pending-save drain and rollback are documented in the infra runbook. No production promotion is implied by a candidate build.
